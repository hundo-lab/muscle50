# muscle50 목표와 우선순위

muscle50이 무엇을 향해 가는지 적은 문서다. 기능을 고르거나 스펙을 쓸 때 이 문서를 기준으로 한다.
사용자가 2026-10-05에 확인했다. 실제 건강 수치는 적지 않는다(현재 값은 InBody 기록을 본다).

## 1. 최종 목표

- 골격근량(SMM)을 늘린다. 1차 목표 **43 kg**, 장기 목표 **50 kg**에 가깝게.
  두 값은 `src/muscle50/domain/training_goals.py`의 `skeletal_muscle_mass_milestone_kg`, `_long_term_kg`와 같다.
- 동시에 **불필요한 체지방 증가를 최소화**한다(근육 증가 중심의 recomposition).
- 수영(1500 m 연속, 목표 페이스)은 보조 목표다. 근력 훈련과의 피로 간섭을 관리한다.

## 2. 실제로 쓸 수 있는 데이터

| 데이터 | 빈도 | 비고 |
|---|---|---|
| Garmin 운동(근력 set, 수영 lap) | 운동할 때마다 | `muscle50 daily`로 동기화 |
| Garmin 회복(수면, HRV, readiness 등) | 매일 | `muscle50 daily`로 동기화 |
| 식사 기록 | 매 끼니(사용자가 직접 입력) | `muscle50 nutrition log` |
| **InBody 체성분** | **한 달에 1~2회** | Samsung Health export → `muscle50 inbody sync` |
| 매일 체중 | **없음** | 사용자는 매일 체중을 재지 않는다. 체중 입력 기능을 만들지 않는다. |

설계에 주는 결과:

- 체성분 판단(근육이 늘고 있나, 지방이 늘고 있나)은 **InBody 측정과 측정 사이**(보통 2~4주)를 단위로 한다.
  주 단위 체중 추세를 전제로 한 기능은 만들지 않는다.
- 측정 사이 기간에는 근력 진척, 근육별 주당 set, 식단(특히 단백질·kcal 목표 준수), 회복을 본다.
- 칼로리 조정 권고는 "다음 InBody까지 유지 / 약 +100~150 kcal / 약 -100~150 kcal, 탄수 조정, 훈련 볼륨 조정"
  형태이며, InBody 두 번 이상과 그 사이 식단 기록이 있어야 의미가 있다.

## 3. 원하는 사용 흐름

### 하루

1. 아침: `daily`로 Garmin 운동·회복 동기화 → 회복 상태와 오늘 운동 추천(현재 동작).
2. 낮: 먹은 것을 기록 → 남은 단백질·kcal 확인 → 다음 끼니 메뉴 추천(실제 단위: 햇반 1개, 닭가슴살 1~2팩 등).
3. 운동 전후: 운동 전/후 식사 안내.
4. 하루 끝: 운동, 식단, 회복 요약.

### InBody 측정 사이(2~4주)와 측정 직후

- 체성분 변화(골격근량, 체지방량, 체중)와 1차 목표(43 kg)까지 남은 양.
- 그 기간의 근력 진척, 근육별 주당 set, 식단 준수, 회복을 한 화면에서 본다.
- 다음 측정까지의 조정(유지 / kcal 소폭 증감 / 탄수 / 훈련 볼륨)을 권고한다.

### 나중에

- Telegram 등 채팅으로 묻기: "오늘 뭐 운동해?", "점심 뭐 먹지?", "단백질 얼마 남았어?",
  "근육 증가 방향 괜찮아?". 기존 use case를 그대로 부르는 얇은 층으로 만든다.
  - 명령어형 v1은 있다(`muscle50 telegram run`, `docs/telegram-bot.md`). 위와 같은 자유 문장(LLM)은 v2다.

## 4. 현재 상태(2026-10-05)

| 루프 | 상태 |
|---|---|
| 운동 동기화 + 운동 추천(회복, 수영 간섭, 증량 규칙) | 있음 |
| 식사 기록, 하루 섭취, 영양 목표 대비 status, 운동 계획 옆 안내 | 있음(입력은 food ID 또는 정확한 이름/alias, 식사 void/edit/merge 있음) |
| 체성분 추세(InBody 측정 사이 변화, 목표까지 남은 양) | 있음(v1): `muscle50 inbody trend`(read-only, `docs/inbody-trend.md`). 추천에는 아직 쓰지 않는다 |
| 측정 사이 리뷰(체성분 + 근력 + set + 식단 + 회복) | 없음 |
| 칼로리/탄수/볼륨 조정 권고 | 없음 |
| 메뉴 추천 | 없음 |
| 채팅 인터페이스 | 있음(v1, 명령어형): `muscle50 telegram run`, `docs/telegram-bot.md`. 자유 문장(LLM)은 v2 |

## 5. 우선순위

1. 이 문서.
2. **InBody 체성분 추세**(`docs/specs/inbody-trend.md`): 측정 목록, 측정 사이 변화, 43 kg까지 남은 양.
3. **음식 이름으로 식사 기록**(`docs/specs/food-name-lookup.md`): 매일 기록 마찰을 줄여 식단 데이터를 쌓는다.
4. **측정 사이 리뷰 리포트**: 체성분 추세 + 근력 진척 + 근육별 set + 식단 준수 + 회복.
5. 데이터가 쌓인 뒤(InBody 2회 이상 + 그 사이 식단 기록): 칼로리/탄수/볼륨 조정 권고 → 메뉴 추천.

2026-10-06 사용자 결정: 채팅을 앞당긴다. 2, 3은 통합됐고, 다음은 **Telegram 명령어 bot v1**
(`docs/specs/telegram-bot.md`, LLM 없음)이다. 자유 문장(LLM)은 v2에서 그 위에 얹는다. 그다음 4, 5 순서다.
2026-10-07: Telegram 명령어 bot v1이 통합됐다. 다음은 4, 5 또는 Telegram 자유 문장(LLM) v2다.

목표에 직접 기여하지 않는 정리 작업(`auto-load-metrics`, `sync-coverage`, `meal-void-edit` 등)은 위 순서를
막지 않을 때 하거나, 실제로 불편해졌을 때 한다.

## 6. 스펙을 쓸 때

- "목적" 절에 이 문서의 어느 루프나 우선순위에 기여하는지 적는다.
- 판단을 내리는 기능(조정 권고, 메뉴 추천)은 데이터가 부족하면 판단하지 않고 무엇이 부족한지 말한다.
  `.claude/skills/domain-principles`(결측은 0이 아님, 추측 금지)가 그대로 적용된다.
